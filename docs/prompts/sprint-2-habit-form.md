## Задачи

### 1. Расширение схемы `Habit` (миграция v1 → v2)

В `src/services/storage.js` добавить миграцию `1 → 2`:

```js
migrations[1] = (data) => {
  data.habits = (data.habits || []).map(h => ({
    ...h,
    activeDays: h.activeDays ?? [0,1,2,3,4,5,6], // Пн..Вс
    endDate: h.endDate ?? null,
    startWeight: h.startWeight ?? null,
    weightGoal: h.weightGoal ?? (h.type === 'weight' ? 'maintain' : undefined),
  }));
  return { ...data, version: 2 };
};
```

В `src/types/habit.ts` `activeDays: number[]` — обязательное поле после миграции.

### 2. Редизайн `HabitFormModal` — пошаговый мастер

Переписать модалку как 4-шаговый wizard (нижний stepper). Каждый шаг — отдельный компонент в `src/components/habitForm/`:

```
src/components/habitForm/
  Step1_Type.js          // выбор типа: boolean/number/weight
  Step2_Identity.js      // имя, описание, иконка, цвет, категория
  Step3_Goal.js          // цель: targetValue+unit (для number) / targetWeight+startWeight+goal (для weight) / только tick (для boolean)
  Step4_Schedule.js      // дни недели, targetDaysPerWeek (авто из выбранных), endDate, reminderTime, reminderEnabled
  StepIndicator.js       // индикатор шагов 1/4 сверху
  HabitFormWizard.js     // контейнер, state, навигация
```

Правила:
- Кнопка "Далее" на шаге дизейблится, пока обязательные поля не заполнены.
- Кнопка "Назад" всегда возвращает на предыдущий шаг без потери state.
- При редактировании (`editingHabit != null`) при открытии wizard **переходить сразу на нужный шаг**, если пользователь перешёл в редактирование определённой секции (issue #21: "открытие нужной страницы с цветом при повторном выборе и с категорий и иконкой"):
  - Проп `initialStep: 1 | 2 | 3 | 4` в `HabitFormWizard`.
  - В `HabitCard` меню действий: кнопка "Редактировать" может открывать шаг 2 (identity). В settings карточки (появится в Sprint 5 через bottom sheet) — можно быстро прыгнуть на конкретный шаг.
- Валидация — реюзать `src/utils/validation.js` из Спринта 1.

### 3. Step 1 — выбор типа привычки (issue #21 первый пункт)

- Три большие кнопки-карточки: `Выполнить/Не выполнить`, `Количественная`, `Отслеживание веса`.
- При тапе выбирается тип, кнопка "Далее" активна.
- При редактировании — тип показывается disabled с подписью "Тип нельзя изменить после создания".

### 4. Step 3 — Цель

**boolean:**
- Ничего не показываем, только текст "Простая привычка: сделал/не сделал".

**number:**
- Числовое поле `targetValue`, минимум 1.
- Селект `unit` из `MEASUREMENT_UNITS` (табы по типам: время / количество / объём / расстояние).
- Чекбокс "Разрешить перевыполнение".

**weight:**
- `startWeight` (текущий вес), `targetWeight` (цель), `weightGoal` — сегментированный контрол `Сбросить / Набрать / Поддерживать`.
- Автоопределение: если targetWeight < startWeight → предлагаем `lose`, если > → `gain`, если равен → `maintain`.
- Валидация 20..300 kg.

### 5. Step 4 — Расписание (issue #16, #17)

**Дни недели (issue #17):**
- 7 кнопок-чекбоксов `Пн Вт Ср Чт Пт Сб Вс`.
- По умолчанию все выбраны.
- Внизу — селектор "Плановая частота" (`targetDaysPerWeek`) с двумя опциями:
  - **Auto (по умолчанию)** — равна количеству выбранных дней.
  - **Кастом** — можно поставить меньше (напр., 5 из 7 выбранных дней). Тогда план считается как min(activeDays.length, targetDaysPerWeek).

**Срок привычки (issue #16):**
- Радио: `Бессрочно` / `На N дней`.
- При `На N дней`:
  - Числовое поле дней (7 / 14 / 21 / 30 / кастом).
  - Показ даты окончания: "до 15 октября 2026".
  - Хранится как `endDate: ISO string`.

**Напоминание:**
- Свитч `reminderEnabled`.
- Time picker `reminderTime` (`HH:MM`).

### 6. Изменения в расчётах (используют Спринт-1 API)

#### `src/utils/completion.js` — `getPlannedDaysInPeriod(habit, startDate, endDate)`

Возвращает число дней в периоде, когда привычка запланирована:
- Учитывает `habit.activeDays` (только выбранные дни недели).
- Обрезается по `habit.createdAt` и `habit.endDate`.
- Ограничивается `habit.targetDaysPerWeek`, если задан кастомный (пропорционально по неделям).

Все места, которые считали план от общего числа дней в периоде (`StatisticsScreen.calculatePlanFromCreation`) — переписать на новый helper.

#### `src/utils/streak.js`

При проверке дня для serie: если день **не входит в `activeDays`** — считать как skip (не ломает серию, не добавляет к ней).

### 7. Автоархивация по истечении срока (issue #16)

При старте приложения (в `useHabits`-init):
- Для каждой привычки с `endDate < today` — вызвать `archiveHabit(id)` автоматически с флагом `autoArchived: true`.
- В `ArchiveScreen` показывать бейдж "⏱ Срок вышел" на таких привычках.

### 8. Issue #14 — default values при редактировании статистики

В статистике (WeekStatistics / MonthStatistics), когда пользователь тапает на ячейку дня чтобы ввести/поправить факт:
- Открывается модалка ввода.
- Если текущий факт `=0` (нет completion), **предзаполнить полем плановое значение** (`habit.targetValue` для number, `habit.targetWeight` для weight, `true` для boolean).
- Если факт уже есть — предзаполнить фактическим значением.
- Кнопка "Установить план" — быстро возвращает поле в плановое значение.

### 9. UX для редактирования из карточки

В `HabitCard`, кнопка редактирования открывает `HabitFormWizard` с `initialStep=2` (identity).

В будущей карточке настроек привычки (Sprint 5) — quick-jump кнопки на конкретные шаги.
